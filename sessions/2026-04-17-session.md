# Sesión — 2026-04-17

## Tema principal
Implementación de TabPFN como modelo fundacional para potencialmente añadir al ensemble; resolución de problemas de entorno (autenticación, DLL, rendimiento).

## Decisiones tomadas
- **TabPFN en CPU descartado para OOF completo**: 200 muestras = 332s → ~4h para 5-fold OOF. Inviable en producción.
- **Conflicto DLL pandas + torch en Windows resuelto**: `torch`/`tabpfn` deben importarse antes que `pandas` en scripts (WinError 1114).
- **Autenticación TabPFN**: el `.env` ya tenía `TABPFN_TOKEN` directamente (no `PRIORLABS_API_KEY`). `load_dotenv()` antes del import es suficiente.
- **Pendiente de decisión**: tres opciones para continuar con TabPFN: (a) `tabpfn-client` cloud API, (b) otro modelo con diversidad arquitectural (ExtraTrees, LogisticRegression), (c) submission directa sin OOF.

## Trabajo realizado
- Creado `scripts/10_tabpfn_train.py` — script completo con OOF 5-fold, fit final, submission y metadata JSON, siguiendo el patrón de `08_catboost_native.py`.
- Orden de imports corregido en el script (torch antes que pandas).
- Benchmark de rendimiento: fold real (6,811 train / 1,703 val), 4 estimators → fit: 0.7s, predict 200 muestras: 332s.

## Conclusiones
- TabPFN v2 en CPU no es viable para datasets de >1,000 muestras sin GPU. El script está listo pero inutilizable en local sin cambiar la estrategia de inferencia.
- El conflicto torch/pandas en Windows es reproducible y sistemático: cualquier script que importe `pandas` antes de `torch` falla con WinError 1114.
